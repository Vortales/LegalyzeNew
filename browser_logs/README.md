# browser_logs — папка обмена логами браузера

Сюда вы кладёте логи работы браузера, по которым я разбираю поведение и правлю
приложение. Здесь же появляются готовые разборы.

```
browser_logs/
├── README.md        этот файл
├── inbox/           ← СЮДА кидать логи (по одной папке или zip на случай)
└── analyzed/        ← сюда автоматически кладутся разборы ANALYSIS.md
```

## Что именно кидать

Целиком **папку сессии** из `%APPDATA%\Legalyze\logs\`, например:

```
%APPDATA%\Legalyze\logs\20261004-181233-21432-a1b2c3
```

Копируйте папку целиком — там лежит всё, что нужно:

| Файл | Что показывает |
|---|---|
| `UNDERSTANDING.md` | **готовый вывод**: когда браузер съезжал, встал ли на место, прикрепились ли файлы |
| `browser-window-timeline.txt` | построчная хронология окна в миллисекундах (мельчайшие детали «съехало — вернулось») |
| `browser-trace.txt` | каждый вызов Win32 к окну: куда просили поставить, где оказалось, почему разошлось |
| `browser-trace-summary.json` | машинный итог: счётчики причин и вердиктов |
| `page-code-*.html`, `page-outline-*.json` | «код страницы» без текста и секретов: структура, классы, геометрия |
| `diagnostic.jsonl` | полный журнал приложения: CDP, поверхность, экспорт, ошибки |
| `events.log`, `summary.json` | человеческие строки и итог диагностики |

Можно и просто заархивировать папку в `.zip` — я распакую сам.

**С v20 в папке появились две вещи, которые отвечают за «а у другого
пользователя не работает»** (подробности — `ТЗ_ДИАГНОСТИКА.md`):

| Что | Где | Зачем |
|---|---|---|
| **Паспорт машины** | `machine.fingerprint` в `browser-trace.jsonl` (и `machine.summary` — коротко) | Windows и сборка, масштаб экрана (100/125/150 %), сколько мониторов, RDP или обычный вход, тёмная тема, права, панель задач. Две машины сравниваются по одинаковым числам, а не «на глаз» |
| **Самопроверка** | `selfcheck.*` там же | приложение само пишет вердикт по подсистемам: `engine`, `native_browser`, `hotkeys`, `mic`, `layout`, `window_position`, `export`, `admin_free` — с «ок / не ок» и подсказкой, что делать |

Разбор показывает их разделом **«0. Машина и проверки»** и отдельно пишет
**риски этой машины** (например, «масштаб экрана 150 %» или «сессия RDP») —
чтобы не гадать, почему у вас работает, а у пользователя нет.

Если сессия старая (до v20) — разбор честно пишет «паспорт не записан» и
**не выдумывает риски**: догадки в отчёт не попадают.

## Имя папки/архива — по возможности так

```
<дата>-<кто>-<что-не-так>
2026-10-04-ivan-f2-sdvig-2-3-sek
2026-10-04-petr-fajly-ne-eksportiruyutsya
```

В имени полезно указать **кто** (вы или пользователь), **что делали** (хоткей
«Окно», сворот/разворот, выбор промта, экспорт) и **что увидели**.

## Как кидать

1. Полностью закройте приложение (тогда `UNDERSTANDING.md` и `summary.json`
   точно дописаны).
2. Скопируйте папку сессии в `browser_logs/inbox/`.
3. Напишите мне в чат: что делали и что ожидали увидеть. Чем точнее описание
   (в какое время, какая функция), тем быстрее разбор.

## Что происходит дальше

1. Я запускаю разбор:

   ```
   cd TestLegalUniversal_v19
   python3 tools/analyze_browser_logs.py --list
   python3 tools/analyze_browser_logs.py
   ```

2. В `browser_logs/analyzed/<имя>/` появляются `ANALYSIS.md` и `analysis.json`.
3. По разбору я правлю код, а по факту — обновляю журнал ошибок `ОШИБКИ.md`
   (успешный подход и подходы «НЕ ИСПОЛЬЗОВАТЬ»).

## Приватность и объём

* Сбор **не пишет**: текст ваших запросов, содержимое промтов и PDF, пароли,
  токены, HWID, cookie. Текст страницы вырезается, остаётся структура.
* Пишутся имена файлов, которые создаёт сама программа (`<промт>.pdf`,
  `Шаблон.txt`) — без них нельзя доказать экспорт.
* Одна папка сессии обычно занимает от единиц до десятков мегабайт. Если
  больше 100 МБ — присылайте только `browser-*.txt`, `browser-*.jsonl`,
  `UNDERSTANDING.md`, `summary.json` и `diagnostic.jsonl`.
* Сами логи я не коммичу и не удаляю из этой папки без вашего слова.
